# PR text, template and docs-sync calibration

Measured on 2026-09-24 with `jev-1.13.0`. The 16 rules are the six rules in `jev:pr-template`, seven in `jev:pr-description`, and three in `jev:docs-sync`. This is a measurement of the **production** `judge()` policy, not merely model probabilities. No failures, skipped requests or missing row answers occurred in either final run; final training used 211 requests / 343,678 input tokens / 515 saved answers, and the reserved slice used five requests / 12,741 input tokens / 48 saved answers. `--no-suggest` prevented threshold search. No rule was promoted to `blocker`; even a perfect observed fraction here is not a prospective precision guarantee.

## Data, freeze and diagnosis

`build.py` reads the public PR snapshots in `/tmp/canopy-data/prs_full.json` and `/tmp/canopy-data/pr_files.json`. The 234 training rows comprise 184 historical PR-template rows from `eval/datasets/canopy-pr.jsonl` (145 real PR versions and **39 source-backed text mutations**, marked `synthetic` in `train.jsonl`), 20 constructed PR-description fixtures from `eval/datasets/pr-description.jsonl` (not real PRs), and 30 independently labeled **real changed-code PRs** for docs-sync. The per-rule row counts below are smaller than 234 because only relevant rule labels are carried into each row. PRs 284, 285, 286, 287, 289, including rejected versions of 286/287 in the old dataset, were excluded from all training rows. The five final merged PR texts and their changed-file lists/diffs were separately labeled in `holdout.jsonl` **before** querying Jev on them. The prior `canopy-pr.jsonl` already contained their titles, descriptions and template labels, so the reservation is for *this* tuning, **not a fully blind holdout**.

The shared `eval/anonymize.py` policy recursively replaces unrelated project names with `ExampleProject` and company-specific CI/tracker hosts with example domains in both serialized slices, including nested PR bodies and changed-file patches. It leaves labels and reserved IDs untouched. The rebuilt training JSONL has SHA-256 `086080d083c308350baa4a6717c9c56a28455236181298b881d3f1b4723df1b6`; the reserved JSONL stayed byte-identical (SHA-256 `b938289a98ad4034d0520770fdaf1c46f30de0e6945c53db862fd3daae1d354f`). Neither output contains those source identifiers. The saved training answers replay against this input without API calls; the reserved slice was not queried again or treated as fresh blind validation.

The docs labels require a documentation obligation, not just an `added_lines` regex hit. Examples: PRs 57/58/64/90/94/126/129 add app-facing features without a docs change; PR 12 repairs an already intended restoration workflow (no new docs obligation); PR 91 introduces typed error variants during an internal `neverthrow` refactor (no new public error contract); PR 175 changes the UI by adding a confirmation step (behavior-positive), but re-registers **existing** `app:showInFolder`/`repoConfig:*` IPC handlers (IPC-negative); PRs 227/238/262 change IPC architecture and also change `docs/`; PR 283 is a dependency upgrade with no app workflow change. These include hard correct cases with added handler/error lines and no docs edit. The initial label for PR 175's behavior was corrected **after reading the full PR text and source**: a new confirmation interaction is a real behavior change. That correction was made on the training slice, before the holdout measurement; do not treat its resulting 17/17 as independent evidence. Labels have no second annotator, and PR body/file-list summaries cannot prove every deployed runtime effect.

The initial historical live training run (342,766 input tokens) measured the original prompt: docs behavior confirmed 16/16 labeled positives but falsely confirmed PRs 12 and 175 as then labeled. Its baseline dump and per-row judgments were retired because they do not match the final prompt/data; they must not be replayed. Source inspection changed the PR 175 label to positive, and the docs prompt was narrowed to new user-facing behavior rather than intended behavior restored by a bug fix. Both `pr-template` and `docs-sync` now set `context.include_pr_body: true` so their PR-scope questions receive the description when used alone. The two unconditional docs patterns were disabled after their observed clean-code false positives; the measurement config **temporarily re-enables them** so they still appear in both calibration tables. No threshold was tuned. The sanitized training slice was measured again with a **live API run**, not replayed. All confirmed TP/FP counts remained unchanged; clean `needs_human` fell by one each for `pr.description-what` and `pr.description-testing`, consistent with live-answer variation. Its request fingerprint remained the same as the prior final run despite changed dataset bytes: the changed fields did not alter the serialized model state/questions. A subsequent replay accepted the saved fingerprint against the sanitized data; this replay did not replace live measurement.

## Rule-by-rule final policy and counts

`n + / -` is labeled positives / negatives. `TP/FP` counts **confirmed** findings, not human reviews. `+H/M` counts positive needs-human / positive missed; `-H` counts clean needs-human. The held-out column uses the same format: `+/-; TP/FP; +H/M; -H`. A rule with no positive cases has undefined recall; no held-out-positive claim is made for 15 of 16 rules. `auto advisory; manual adjudication` means a rule remains enabled and **automatically emits `confirmed` findings** that a human must verify before taking action; it does **not** mean Jev routed them as `needs_human`. There is no human-only routing for these Noul rules in the shipped policy. `auto` here never authorizes automatic blocking. Disabled rules are evaluated only by the explicit experimental enable overrides in `jev-review.yml`.

All 16 have zero incomplete labels/evaluations and no abstentions. Precision is undefined for any rule with no confirmed findings in a slice; on the training sample the two disabled patterns would have confirmed precision 13/15 = 86.7% and 6/7 = 85.7%. The PR-title and description-what rules each had 8/9 = 88.9% (the deliberately constructed `DO NOT MERGE - testing deploy pipeline` fixture caused both false findings). The model-based docs rule had 17/17 observed training positives and 13/13 clean negatives, but **zero positives** in the holdout: keep it nonblocking.

The only reserved positive violations were missing ticket references on PRs **285 and 287** (both confirmed). The remaining **15** rule IDs had zero positives in the five reserved PRs; 284 was an install fix, 285 changed docs, 286 repaired broken task sending, and 287/289 replaced icon imports/aliases without visible feature changes. Thus the holdout mainly tests false-positive restraint, not recall. In particular the disabled patterns' holdout silence does not rehabilitate their training false positives.

The first two `pr.*` false positives should not be "fixed" by declaring their original clean fixture to be a violation or by selecting a threshold solely to hide it. No title/description semantic rule is promoted to an automatic merge blocker. The 39 historical text mutations and 20 constructed description fixtures inflate apparent coverage and are not independent real-world violations. Template presence and checklist positives include mixed real and mutated PR bodies; `pr.title-unfinished` and `pr.template-unfilled` have only two fixture positives each. Neither perfect observed fraction nor absence of positives warrants a 100% future claim.

## Reproduce and inspect

Requires Node/npm, Python 3, `/tmp/canopy-data/{prs_full,pr_files}.json`, and `TYPESAFE_API_KEY` in `.env` for live runs. The builder does not read any API answer. Do not feed the reserved PR IDs into the training config.
The builder also requires the private redaction mapping described in `eval/canopy/README.md`.

```sh
python3 eval/calibration/pr-docs/build.py
npm run calibrate -- --data eval/calibration/pr-docs/train.jsonl --config eval/calibration/pr-docs/jev-review.yml --dump eval/calibration/pr-docs/train-final --no-suggest
npm run calibrate -- --data eval/calibration/pr-docs/holdout.jsonl --config eval/calibration/pr-docs/jev-review.yml --dump eval/calibration/pr-docs/holdout-final --no-suggest
# For unchanged question/state/model, policy-only replay (no API):
npm run calibrate -- --data eval/calibration/pr-docs/train.jsonl --config eval/calibration/pr-docs/jev-review.yml --replay eval/calibration/pr-docs/train-final.answers.json --no-suggest
```

The calibration report's `TP/FP`, human/clear counts, preselection and incomplete rows come from the calibrated `judge()` policy. `train-final` and `holdout-final` are complete per-row judgments under this directory; their `*.answers.json` files contain full raw answers, resolved configuration, errors and SHA-256 request fingerprint. The superseded `train-baseline` dump and per-row judgments have been removed; historical baseline results above are diagnosis only. Final fingerprints: sanitized training `30539be44c5bff470a69702291de9a5836493daadf69f073dc79028454171ca8` (515 answers, zero errors), unchanged reserved `e8a4ae39736ee829102d4ae5254382482ca7e94e274c03a2895e8ee7009f4124` (48 answers, zero errors). The current live training report is `eval/reports/calibration-2026-09-24T072109.245Z.md`; a replay against the sanitized data succeeded. The previous training report (`eval/reports/calibration-2026-09-24T064530.992Z.md`) is superseded, not a current replay source; the reserved report remains `eval/reports/calibration-2026-09-24T064555.450Z.md`. Neither temporary enabling of disabled patterns nor this calibration substitutes for evaluating them as production-enabled rules.

Limits: samples come mostly from one public project; the docs examples are enriched for obvious features and regex candidates, so preselection 17/17 or 13/13 is **coverage of labeled candidates, not population recall**. Five reserved PRs provide no behavior/docs/template positives and only two issue-reference positives. The historical template dataset was previously used for preset authoring; the already-present reserved PR titles make full blindness impossible. The live Jev outputs may vary between calls (for example, baseline vs final run changed `template.why-reason` from one positive human to confirmed despite the same question). These numbers do not justify a statistical claim about future precision, location accuracy (all rules are PR-scope or pattern), or applicability to repositories with different docs structure. Build, lint, typecheck, formatting, and project-wide tests are deliberately deferred to the integration owner.
