# Code-slop calibration: 24 rules

**Decision: keep all 24 enabled with automatic, nonblocking advisory findings; none are human-only, disabled, or approved for automatic blocking.** A `confirmed` finding is emitted automatically, not routed to a person; a `needs_human` finding is emitted for human review only when the probability reaches the rule's human-band floor without meeting both confirmation thresholds. In the shipped/default policy, Choice rules confirm at P(present) ≥ 0.6 and confidence ≥ 0.5, and otherwise route P(present) ≥ 0.4 to `needs_human`; `slop.useless-comment` instead uses P(present) ≥ 0.7 for both routes. These are **finding statuses**, not blocking severities: the rules' `info`/`minor`/`major` severities do not fail the check or request changes under the default blocker-only policy. All 24 shipped rules also have `abstain_labels: [insufficient_context]` from preexisting work: an abstention is not a finding, but `abstentions()` records it and `decide()` prevents opt-in `APPROVE` while the default `policy.approve.no_abstentions: true` holds. Approval itself is off by default; abstentions do not independently fail the default check or request changes. Do **not** add `major`/`minor` to a blocking policy based on these observations. No rule has demonstrated real-world precision sufficient for auto-blocking, even the two with ten real-code-derived **mutated**, not natural, positives each. None is disabled in the shipped preset; the absence of observed confirmed false positives in this limited sample is not proof that automatic advisory findings are reliable in deployment. Projects lacking needed contracts may disable individual rules rather than treat abstentions as violations.

## Reproduce and audit

Inputs are public canopy-desktop PR files and metadata from `/tmp/canopy-data/pr_files.json` and `prs_full.json`, plus the existing 62 rule-pack fixture rows and 80 real-code mutation/control rows. `build_data.py` records all chosen natural snippets, labels, sources, and the reserved PR IDs; `natural-label-notes.json` records my independent label reasoning **outside** model context. Do not use holdout PRs 284, 285, 286, 287, or 289 to select prompts, regexes, thresholds, or labels. The generator verifies 24 rule IDs and the existing dataset sizes. Run with the API key read by the project's existing `.env` mechanism; never put it in these files.

```sh
python3 eval/calibration/code-slop/build_data.py
npm run calibrate -- --data eval/calibration/code-slop/tuning.jsonl --config eval/calibration/code-slop/jev-review.yml --dump eval/calibration/code-slop/tuning-final --no-suggest
# Policy-only replay; rejects changed model, state or questions by request fingerprint:
npm run calibrate -- --data eval/calibration/code-slop/tuning.jsonl --config eval/calibration/code-slop/jev-review.yml --replay eval/calibration/code-slop/tuning-final.answers.json --dump eval/calibration/code-slop/tuning-policy --no-suggest
# Run only after policy is frozen and the holdout labels have been written:
npm run calibrate -- --data eval/calibration/code-slop/holdout.jsonl --config eval/calibration/code-slop/jev-review.yml --dump eval/calibration/code-slop/holdout-final --no-suggest
```

`*.answers.json` preserves resolved config, model/state/questions fingerprint and **full** raw answer probabilities/confidences; corresponding extensionless JSONL files contain one row/rule decision and every hunk observation. The calibrator exits nonzero on incomplete evaluations. The live tuning run evaluated 158 rows / 125 requests / **162,555 input tokens**, with zero evaluation errors, skipped requests, oversized/missing answers, or incomplete rows. The frozen holdout evaluated 25 rows / 61 requests / **127,681 input tokens**, also complete. Model: `jev-1.13.0`, 2026-09-24. A prior 142-row fixture+mutation baseline used 110 requests / 132,051 input tokens; it is saved as `baseline` and its report. No model prompt or candidate regex changed, so replay of the 158-row live answers is valid for the one policy change. No threshold optimizer was used as evidence.

## Independent source evidence and diagnosis

The 62 contract-given fixtures include **25 positives, 31 negatives, six unknowns**. The 80 mutation/control rows include **40 positive mutations and 40 controls** from actual canopy calls/tests; their positive defects were injected, not found unprompted. The 16 real PR added-code excerpts are **one natural positive and 27 negative rule labels** (28 labelled row/rule pairs); they are excerpts of source additions, not whole-repository evidence. The sole hand-confirmed unmutated positive, PR #9 `toggleFocusedInspector`, uses `pane.inspectorOpen === false ? true : false`, a redundant boolean wrapper. It was selected but got only **needs-human**, P(present)=0.48/confidence=0.23; this is not a confirmed true positive. Hard, correct natural controls include PR #3's IPC adapter with a disposer, optional favicon failure with a handled rejection, optional toolbar focus, and meaningful event branches; PR #4's untrusted HTTP-header validation; PR #13's documented Electron interop suppression; PR #14's actual app smoke assertion; PR #18's implemented tree with a future-performance TODO and caught reactive file load; PR #52's intentional shell fallback; PR #91's input-tied generic; and PR #96's real addition-count reduction. Their labels are source-code observations rather than model-generated labels. The scripts preserve each source PR and the explanation for each case.

On the 158-row final tuning set there were **56 automatically confirmed positives, zero confirmed false positives, ten positive `needs_human` findings, zero missed positives, zero clean `needs_human` findings**, plus six unknown labels excluded from precision/recall; this is **not** an estimate of deployment precision. Of those 56 true confirmations, 24 came from contract-given fixture positives and 32 from injected real-code mutations; **zero** from an unprompted real PR. `wrapper-chain`'s one fixture positive was sent to a person, while `unawaited-async-work` sent 8/11 mutated positives to a person (three confirmed); the natural boolean positive also went to a person. Unknown-contract cases appropriately produce abstentions (with some low-confidence clears); real PR #4 API usage and the user-initiated browser retry abstained rather than assert a defect. Regex preselection may omit legitimate positives outside its pattern; the test only checks coverage on these labelled examples.

The only production preset adjustment made by this calibration is `slop.useless-comment`: threshold **0.6 → 0.7** and per-rule human band floor **0.4 → 0.7**. The `abstain_labels: [insufficient_context]` entries on all 24 rules were already present in the working tree before this calibration; they are part of shipped behavior, not an outcome of this threshold decision. The real PR #1 `// About` section heading was incorrectly sent to human review at P=0.64/confidence=0.46; this floor clears it. The rule-pack's explicit redundant-comment positive remains **automatically confirmed** at P=0.96/confidence=0.94; the meaningful-comment controls remain clear. At P≥0.7 with confidence<0.5, this rule can still produce `needs_human`; its measured positive did not. A higher floor might also hide other true comments, so the rule stays nonblocking advisory. This is a small **local** policy response to one observed noisy counterexample, not a claimed precision guarantee. The original question/regex was untouched; the policy replay accepted the identical request fingerprint.

The 25-file holdout changed **no observed violation** of these 24 rules. PR #287/#289 mostly replace icon imports and PR #285/#286 fix error display and path equality. Seventeen icon-related `api-mismatch` labels were explicitly marked **unknown** before scoring because the isolated patches do not contain the exact package declarations. Ten of those unknown rows abstained and seven cleared; of the eight prelabelled clean API rows, seven abstained on missing dependency evidence and one cleared. Thus the holdout has **17 `api-mismatch` abstentions** (plus one `duplicated-business-rule` abstention on a clean PR #285 file). No abstention is a confirmed false positive or a `needs_human` finding; under the shipped labels and default `policy.approve.no_abstentions: true`, these abstentions prevent opt-in automatic `APPROVE`, while default approval is disabled and they do not themselves fail the default check or request changes. An `as Task` assertion in PR #286 was prelabelled unknown, but its candidate regex did not select it: the rule's regex only recognizes `as any`, double casts and suppressions, not every `as T`. Do not retune labels to the answers. Unknowns are not negatives in the calibrator, and abstentions are not counted as clean human reviews.

## Limits and promotion gate

The holdout was reserved **before the calibration-driven threshold change**, but it is not fully blind or prospective: these PR titles/descriptions already occur in `eval/datasets/canopy-pr.jsonl`, and prior presets used older canopy data. Its 25 source-file labels are correlated, 0 contain positive defects and most rules have 0 selected candidates; it only probes a narrow clean slice. All positive fixture contracts are stated to Jev, the 40 mutation positives are injected rather than observed defects, and independent annotator agreement is unmeasured. One natural positive remained below confidence for confirmation. `api-mismatch`, `ignored-parameter`, and `duplicated-business-rule` without a candidate regex ask on every eligible hunk even when no dependency contract is shown; the holdout exposes the resulting abstention volume for the first. This matters for consumers who enable approval with `no_abstentions` left at its default, even though approval is off and abstentions do not fail the check or request changes by default. There is no unbiased preselection recall audit, no full-file context beyond a PR diff, no verified line-location accuracy labels, and no evidence of real-world ≥90% precision for **any** rule. The shipped automatic confirmations are **nonblocking by default**, not human-reviewed or validated for use as a blocking gate. A consumer who adds `major`/`minor` to `fail_check` or `request_changes` changes that risk; the present measurements do not justify it. Gather independently labelled natural violations, matched hard counterexamples and a *new* prospective PR holdout before promoting any rule to automatic blocking. Running a threshold optimizer on this dataset does not establish that precision.
