# Convention presets: measured decisions (2026-09-24)

**Shipped decisions:** `async.stale-write` is **human-first**; `theming.hardcoded-color`, `matching.switch-statement`, and `types.any-without-reason` are **disabled**. None is justified as an automatic blocking rule by these measurements. The async Noul threshold is 1 with a human band starting at 0.6: all *observed* findings require a person and `needs_human` does not fail a check. A future answer of exactly 1 could still be confirmed by the current policy engine; this is not a hard human-only guarantee.

## Inputs and reproduction

The reserved evaluation slice is frozen in `../../preset-holdout.json` and `holdout-labels.json`: PRs 284, 285, 286, 287, 289. Their changed code was labeled before running the holdout model. Existing `../../datasets/canopy-pr.jsonl` already contains their titles/descriptions, so this is not historically blind or a prospective performance guarantee. Moreover, two type-training rows originally used PR 286 and the five-PR type holdout was observed before those rows were repaired; its result is **not an independent/blind type holdout measurement**, even after removing the contamination. `/tmp/canopy-data/pr_files.json` supplies exact patches. The isolated `jev-review.yml` copies the path and token/matcher variables from `../../../examples/canopy/jev-review.yml` and explicitly **re-enables the three shipped-disabled rules only for experimental measurement**. The archive contains 233 merged PRs; scans with the experiment config found 132 color-rule hunk hits in 36 PRs, 18 switch-rule hunk hits in 13 PRs, and zero type-rule hunk hits. Hunk-hit totals are not labeled precision estimates.

`async-train.jsonl` retains the 132 preexisting `../../datasets/canopy-code.jsonl` stale-write labels: 17 real violations, 10 *guard-removed mutations of real code*, 105 real clean examples. Deterministic training rows are labeled **added lines extracted from archived PR code**, with source PR/line in each row: `theming-train.jsonl` (8 real violations, 10 real hard negatives), `matching-train.jsonl` (8 real union switches, 6 real clean examples), `types-train.jsonl` (6 real negatives, 4 **explicit mutations**, *no naturally observed positives*; ten distinct paths). No conventions training row cites the reserved PRs 284/285/286/287/289 after the type repair. One-line deterministic patches exercise the added-lines production matcher, not whole-hunk semantic inference. These targeted cases are not an unbiased sample of the 233 PRs.

Run from the repository root with `.env` containing `TYPESAFE_API_KEY` (never include that key in a report):

```sh
npm run --silent scan-patterns -- --files /tmp/canopy-data/pr_files.json --config eval/calibration/conventions/jev-review.yml --samples 30
for r in theming matching types; do npm run --silent calibrate -- --data "eval/calibration/conventions/${r}-train.jsonl" --config eval/calibration/conventions/jev-review.yml --dump "eval/calibration/conventions/${r}-baseline.jsonl" --no-suggest; done
npm run --silent calibrate -- --data eval/calibration/conventions/async-train.jsonl --config eval/calibration/conventions/jev-review.yml --dump eval/calibration/conventions/async-revised.jsonl --no-suggest
npm run --silent calibrate -- --data eval/calibration/conventions/async-train.jsonl --config eval/calibration/conventions/jev-review.yml --replay eval/calibration/conventions/async-revised.jsonl.answers.json --dump eval/calibration/conventions/async-final.jsonl --no-suggest
npm run --silent calibrate -- --data eval/calibration/conventions/holdout.jsonl --config eval/calibration/conventions/jev-review.yml --dump eval/calibration/conventions/holdout-final.jsonl --no-suggest
```

The pre-edit async API baseline (`async-baseline.jsonl`) used the original question, threshold 0.7 and default human band; `async-revised.jsonl` is a **new live API evaluation** after changing question text and its policy to threshold 0.85/band 0.6. `async-final.jsonl` replays *those revised* answers after moving the policy threshold to 1 without changing the question. The calibrator checks the model/state/questions fingerprint on replay. Every `*.jsonl.answers.json` holds the resolved config, full raw API responses, usage, error list and request fingerprint. Zero requests were needed for deterministic rules; async baseline used 171,461 input tokens, revised 181,625, and frozen holdout 45,485. All these runs had **zero incomplete rows**. `--no-suggest` prevents treating an arbitrary threshold search as evidence of precision.

Counts are per **labeled row**, not per every matching line in a large PR. Columns are confirmed true/false positives, positive rows sent to human/missed, and clean rows sent to human. No confirmed predictions means precision **n/a**, not 100%. Confirmed precision/recall applies only to these labeled examples.

**Theming:** negatives include Jira/YouTrack brand artwork (`TrackerProviderIcon.svelte`, PRs 324/344), unchanged identity-green QR corner color during the token migration (PR 195), literal `&#8593;`/`&#8595;` HTML entities (PR 79), and a neutral black Tailwind shadow (PR 195). The latter three are false matches even though the intent is not a new theme surface color. The existing CSS `box-shadow` ignore, token stylesheet exclusion and notch overlay exclusion worked on their sampled rows. A token-only `background: var(--color-bg)` is correctly clear. A single general-purpose line regex cannot safely exempt branding without also missing literal styling elsewhere; do not special-case these PRs to inflate precision. The real positives include hardcoded CSS rgba/hex, `rgb(...)`, JS-generated CSS, `oklch(...)`, and a terminal fallback color in Svelte.

**Matching:** true examples branch on `DropZone`, `SessionStatusType`, watcher event types and discriminated message kinds. False matches branch on unconstrained `KeyboardEvent.key`, file extension text, provider `string` and untrusted JSON `v.type`; `.with(...)` chains in PR 195 are clean. This is a semantic type question, not detectable by the current regex without suppressing real cases. Rewording a deterministic description does not change its matches.

**Types:** real TeamCity `running:any` string literals, typed casts and `unknown` (including PR 14's test-boundary `as unknown as CanopyWindow` at line 103) are clean. The PR 37 terminal focus handler's `e as CustomEvent<{ sessionId: string }>` (added line 73) replaces the contaminated PR 286 clean cast; a PR 3 DOM event target typed cast (line 12) is another hard negative. Archived PR 344's real `event: any, payload: any` has an immediately preceding documented `eslint-disable-next-line`; omitting that suppression in a one-line mutation, changing the PR 33 Gemini preferences `JSON.parse(raw) as Record<string, string>` (added line 17) to `as any`, and changing a PR 33 `toolResponse?: unknown` (line 108) to `?: any` are labeled mutations, not naturally observed regressions. The PR 33 cast mutation replaces the contaminated PR 286 positive. To avoid duplicate paths, the earlier PR 344 clean/ordinary-signature rows, PR 129 positive mutation and second PR 344 mutation were replaced with distinct-path PR 14/3/33 examples. A fourth mutation changes PR 3 `data: unknown` (line 457) to `data:any`; the existing `:\s+any` matcher misses this valid TypeScript despite matching the three other mutations. All four mutations reached deterministic preselection, but this last one failed the pattern check itself. The archive scan had zero findings with the production matcher, so claiming 100% production precision or recall would be unsupported.

The unrelated project name in PR 344's TeamCity test locator is replaced with `ExampleProject` in the saved type-rule row. This changes no pattern decision; `types-baseline.jsonl.answers.json` was regenerated for the sanitized input without API requests.

**Async:** the original live baseline confirmed **12/27** positives and **1/105** false positive, sent **10** positives and **20** clean rows to humans, and missed **5** positives; all 27 positives reached model preselection. The revised prompt clarifies that a guard around `finally`/loading alone is not a guard for a preceding result write, and that an action writing global selected-repo state is not automatically safe. At its intermediate 0.85 threshold it confirmed **5/27**, zero false positives, sent **19** positives and **14** clean rows to humans, and missed **3**. The *final policy replay* moves those five to humans: **24/27** human, **3/27** missed, **14/105** clean human; of the 27 positives, 17 are real (**15 human, 2 missed**) and ten are guard-removed mutations (**9 human, 1 missed**). Remaining missed rows are `stale-write-pr94-taskTracker.svelte-29/-30` (global repo config written for an obsolete repo) and `stale-write-pr324-TaskPanel-99` (removed currency guard): scores 0.55, 0.57, 0.57, all **selected and answered**. These are question/model or policy misses, **not** path/candidate preselection misses. The 14 unnecessary human reviews likewise need triage; no recall/precision guarantee follows from five intermediate correct confirmations.
